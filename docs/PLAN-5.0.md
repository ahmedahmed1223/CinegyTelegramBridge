# خطة تنفيذ الإصدار 5.0

آخر تحديث: 2026-08-23 — **نُفِّذت المراحل أ–د وشُحنت في `5.0.0`.**
خط الأساس كان `4.3.1` بـ307 اختبار؛ الحصيلة **341 اختباراً** وبوابة تفشل الآن
عند `Warning` بصفر نتائج قابلة للتنفيذ.

| المرحلة | الحالة |
|---------|--------|
| أ — التفكيك | ✅ 317 دالة إلى 14 جزءاً؛ الملف الرئيسي 7407 → 973 |
| ب — الإزاحات | ✅ 40 موقعاً إلى `Get-CallbackArg`؛ `$Event` أُعيد تسميته |
| ج — سلامة الهواء | ✅ قاطع دائرة Cinegy، `retry_after`، توحيد إقرار الأزرار |
| د — النظافة | ✅ البوابة ترفض التحذيرات؛ قسم الأخبار مطبَّع |
| و — الواجهة | ✅ القائمة تبدأ بما هو على الهواء؛ تجميع أدوات الإدارة |
| هـ — بوابة النشر | ⛔ **محجوبة — تحتاج قرارك** |

## و — تحسينات الواجهة (مضافة بعد اعتماد الخطة)

القائمة الرئيسية بلغت ~19 صفاً للمشرف، وأزرار إخفاء الطبقات الحيّة كانت عند
الصف السابع تقريباً — **تحت** الأزرار التي تضع المزيد على الهواء.

- الطبقات الحيّة تُعرض أولاً، و«🚨 إخفاء الكل» تحتها مباشرة. لا شيء يُحذف: حين
  لا يوجد شيء على الهواء، يبقى «إخفاء الكل» في موضعه السابق.
- نصّ القائمة صار يقول ما هو على الهواء بدل «اختر من القائمة:»، فيوفّر نقرة على
  «ℹ️ الحالة».
- خمسة صفوف من إعدادات الإدارة النادرة انتقلت خلف «🗂 أدوات الإدارة». الإعدادات
  وطلبات الوصول بقيت بنقرة واحدة لأنها تُستخدم أثناء الوردية. **المشغّل لا يرى
  أي تغيير.**
- `TemplateTestLayer` صار يرفض طبقة يشغلها قالب إنتاج، ويُسمّي القوالب
  المتعارضة — وإلا خرجت «التجربة» على طبقة برامج.

## هـ — ما يحجب بوابة النشر

| البند | الحاجب | ما يلزم منك |
|-------|--------|--------------|
| توقيع Authenticode | لا شهادة Code Signing صالحة في مخزن المستخدم | شهادة حقيقية؛ آلية البناء جاهزة في [Build-Release.ps1:51](../Build-Release.ps1) وتنتظرها فقط |
| دورة SHOW/HIDE حية | `TemplateTestLayer=0` | تحديد رقم طبقة **غير مستخدمة في البرامج**؛ قرار تشغيلي لا يجوز افتراضه — والحارس الجديد يرفض الخطأ الشائع فيه |

**ما يبقى غير مُتحقَّق منه:** السلوك الحي مع Telegram وCinegy. الاختبارات لا تلمس
أياً منهما، فيبقى اختبار الدخان في Telegram شرطاً قبل الهواء.

هذه وثيقة تنفيذ. البنود المؤسسية المخطّطة لـ5.0 في
[DEVELOPMENT-PLAN.md](../DEVELOPMENT-PLAN.md) منفّذة أصلاً (DPAPI، تدقيق JSONL،
وضع الصيانة، حزمة الإصدار، CI). المتبقّي هو **تفكيك الكود** ثم **تصليب التشغيل**.

## 0. لماذا التفكيك أولاً

استراتيجية v4.2 كانت «استخرج المنطق النقي إلى `Modules/*.psm1`». قياس فعلي
بتحليل AST على `TelegramBridge.ps1`:

| المقياس | القيمة |
|---------|--------|
| إجمالي الدوال | 317 |
| إجمالي الأسطر | 7407 |
| دوال نقية **مباشرةً** (لا تلمس `$script:`/`$config`) | 154 — 2127 سطراً |
| دوال نقية **بالوراثة** (ولا تستدعي دالة غير نقية) | **30 فقط — 381 سطراً (5%)** |

**الاستراتيجية القديمة وصلت سقفها.** ما يسدّ الطريق هو `Get-Setting` تحديداً:

| لو عُوملت كخدمة متاحة | السطح القابل للفصل كوحدة |
|------------------------|--------------------------|
| لا شيء (الوضع الحالي) | 30 دالة / 381 سطر |
| `Get-Setting` + `Get-SettingInt` + `$config` | 75 دالة / 852 سطر |
| + `Write-BridgeLog` | 75 دالة / 852 سطر (**بلا أثر** — السجل ليس عائقاً) |
| + دوال إرسال Telegram | 84 دالة / 1004 أسطر |

حتى في أفضل الحالات، 1004 أسطر من 7407 = 14%. الباقي **ذو حالة حقيقية**
(`$script:OnAir`، الطوابير، المسودات، الموزّع) ولا يمكن أن يصبح وحدة `.psm1`
دون إعادة كتابة شاملة — وهي مرفوضة صراحةً في مبادئ النطاق.

### المسار الصحيح: ملفات جزئية مُدرَجة بنقطة

`.psm1` له نطاق معزول ⇒ يتطلّب نقاءً. أما `. ./Parts/X.ps1` فيعمل **في النطاق
نفسه** ⇒ يقبل أي كود مهما كانت حالته.

أُثبت ذلك تجريبياً قبل اعتماد الخطة. الملف الجزئي:

- يرى `$script:` الخاص بالسكربت الرئيسي؛
- يستدعي دوالّ معرّفة **بعده** في الملف الرئيسي (PowerShell يحلّ عند الاستدعاء)؛
- يعمل تحت `Set-StrictMode -Version Latest`؛
- يعمل عبر مسار `. TelegramBridge.ps1 -LoadOnly` الذي تستخدمه الاختبارات.

**النتيجة: تفكيك بصفر إعادة هيكلة للحالة، وصفر تغيير سلوكي، وبلا أي تعديل على
الاختبارات القائمة** — بشرط نقل الدوال وحدها وإبقاء التهيئة في مكانها (أ-0).

## المرحلة أ — التفكيك (تبدأ أولاً)

### أ-0. القاعدة الحاكمة: تُنقل الدوال فقط

الملف **ليس تعريفات فقط**. قياس AST: **64 عبارة تنفيذية على المستوى الأعلى
(91 سطراً)** متداخلة بين الدوال، تُهيّئ الحالة وتعتمد على `$config`:

```powershell
$relayPidFile  = Join-Path $logDir "relay.pid"
$onAirFile     = Join-Path $logDir "onair.json"
$apiBase       = "https://api.telegram.org/bot$($config.BotToken)"
```

القصّ بنطاق أسطر متّصل يبتلع هذه العبارات ويُدرجها **قبل** بناء `$config`
⇒ انهيار فوري. أُثبت ذلك عملياً: تجربة جافة بنطاقات أسطر أنتجت **257 اختباراً
فاشلاً** عند `Parts/Bridge.Core.ps1:239` برسالة
`The variable '$config' cannot be retrieved because it has not been set`.

**القاعدة: يُستخرج امتداد كل دالة عبر AST؛ يبقى كل ما عداه — التهيئة والتعليقات
والإقلاع — في `TelegramBridge.ps1` بترتيبه الأصلي.** ترتيب تعريف الدوال غير مهم
(PowerShell يحلّ عند الاستدعاء)، أما ترتيب التهيئة فمهم — ولذلك لا تتحرك.

خطر مماثل ثبت في التجربة: النطاق `7068–7276` كان سيبتلع
`if ($LoadOnly) { return }`. و`return` داخل ملف مُدرَج يُنهي **الملف** لا السكربت
⇒ تنطلق حلقة الاستقصاء أثناء الاختبارات. الحدّ الصحيح هو 7235.

### أ-1. التجهيز

- إنشاء `Parts/`، وإدراج الأجزاء بعد `Import-Module` الأخير (السطر 68) حيث
  `$scriptRoot` معرّف أصلاً عند السطر 55. الإدراج قبل التهيئة مقصود: العبارات
  تستدعي دوالّ، فيجب أن تكون معرّفة أولاً.

## المرحلة ب — سدّ فئة عطل الإزاحات

تنفَّذ **بعد** التفكيك: ب-1 تلمس 55 موقعاً كلها داخل `Parts/Bridge.Callbacks.ps1`،
فتصبح مراجعة الـdiff ممكنة.

### ب-1. موزّع واحد لتحليل `callback_data`

المشكلة: **55** إزاحة `.Substring(N)` مكتوبة يدوياً. أنتجت عطلاً إنتاجياً فعلياً
(`d50e39e`: الإزاحة الصحيحة 11 لا 10). أي تعديل على بادئة زر يكسر الرقم صامتاً.

```powershell
# ponytail: بادئة + وسائط، بلا سجل توجيه — الـswitch القائم يبقى كما هو
function Split-CallbackData {
    param([Parameter(Mandatory)][string]$Data)
    $parts = $Data -split ':'
    [pscustomobject]@{ Prefix = $parts[0]; Args = @($parts[1..($parts.Count - 1)]) }
}
```

ثم `$data.Substring(11)` ← `$cb.Args[1]`. تعديل ميكانيكي، بلا تغيير سلوك،
**يزيل فئة الخطأ نهائياً**.

### ب-2. اختبار تكامل الأزرار

اختبار واحد يستخرج كل `callback_data` من `Parts/Bridge.Keyboards.ps1` ويؤكّد أن
`Invoke-CallbackQuery` تملك فرعاً مطابقاً. يمسك الأزرار الميتة والفروع اليتيمة
دون كتابة 50 اختباراً. التغطية الحالية: 16 فرعاً من ~50.

### ب-3. إعادة تسمية `$Event`

`$Event` متغيّر تلقائي في PowerShell ومُستخدَم كاسم معامل في
`Write-AuditRecord` و`Add-AuditEntry`. يُعاد تسميته إلى `$EventName`.

## المرحلة ج — سلامة الهواء

### ج-1. عزل Cinegy عن حلقة الاستقصاء

`Update-CinegyStateWatchdog` تستدعي Cinegy عبر HTTP **متزامن** لكل طبقة، كل دورة.
Air معطّل ⇒ البوت يتجمّد `عدد_الطبقات × timeout` كل دورة. التعليق في
`Get-AirTimeout` يوثّق الخطر أصلاً ويُشير إلى زرّ «إخفاء الكل» الطارئ.

قاطع دائرة: بعد N إخفاقات متتالية، تباعُد أُسّي للفحص (3s → 60s سقفاً).

> السلّم: لا خيوط، لا وظائف خلفية. عدّاد + طابع زمني في
> `$script:HealthHistory.Cinegy` الموجود أصلاً. ~20 سطراً + اختبار.

### ج-2. احترام `retry_after`

`Invoke-BridgeTelegramRequest` لا تعالج HTTP 429 — تعيد المحاولة مرتين بـ400ms
ثابتة ثم تُسقط الرسالة مع تسجيلها فقط. تُقرأ `retry_after` من جسم 429 ويُنام
بالمدة المطلوبة، مع رفع `MaxAttempts` الافتراضي إلى 3.

> وحدة نقية باختبارات قائمة — أرخص موضع تعديل في المستودع.

### ج-3. توحيد مسار Telegram

`Get-TelegramUpdates` و`Confirm-TelegramCallback` تتجاوزان غلاف إعادة المحاولة
وتستخدمان `Invoke-RestMethod` خاماً. تُوجَّهان عبر `Invoke-BridgeTelegramRequest`.

## المرحلة د — النظافة

### د-1. رفع بوابة Analyzer

البوابة تفشل عند `Error` فقط، فتمرّ 354 نتيجة `Warning`. تُرفع لتفشل عند
`Warning` مع الاستثناءات التجميلية المعتمدة أصلاً
(`PSAvoidUsingWriteHost`, `PSUseShouldProcessForStateChangingFunctions`,
`PSUseSingularNouns`, `PSUseBOMForUnicodeEncodedFile`, `PSUseApprovedVerbs`).
المتبقّي الحقيقي: 8 نتائج فقط — منها `$Event` (ب-3).

### د-2. تطبيع قسم الأخبار

`news:*` مكتوب بأسطر مضغوطة بفواصل `;` بعكس أسلوب بقية الملف، ما يجعل الـdiff
غير قابل للمراجعة. يُفكّ ليطابق الأسلوب السائد. **بلا تغيير منطقي.**
