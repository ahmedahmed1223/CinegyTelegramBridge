# مهام بناء الإصدار 3

## المرحلة 1 — سلامة مسار العرض

- [ ] **[2] قفل الطبقة أثناء التجهيز:** إنشاء مخزن أقفال قصير العمر في `TelegramBridge.ps1` يربط الطبقة بالمستخدم والمسودة، ويمنع مستخدمًا ثانيًا من تجهيز الطبقة نفسها حتى الإرسال أو الإلغاء أو انتهاء المهلة. يكتمل عند ظهور سبب الرفض واسم/معرّف الحاجز بصورة آمنة. _ينشئ منطق قفل جديدًا ويعدّل حالات المحادثة الحالية._
- [ ] **[3] الحقول الإلزامية:** تعديل تحميل القوالب وتدفق الإدخال لتمييز الحقول الإلزامية ورفض القيمة الفارغة قبل الإرسال، مع رسالة تحدد الحقل المطلوب. _يعدّل `Get-TemplateStore` و`Resume-ShowFlow` ويعيد استخدام حدود الحقول الحالية._
- [ ] **[12] مؤشر تقدم الحقول:** عرض «الحقل س من ص» في كل خطوة إدخال مع اسم الحقل وحده، بما يشمل القوالب ذات الحقل الواحد. _يعدّل `Get-FieldPromptText` ويعيد استخدام حالة العرض الحالية._
- [ ] **[13] التنقل والتحرير والمعاينة والإلغاء:** إضافة أزرار السابق والتعديل والمعاينة والإلغاء إلى تدفق واحد متماسك، مع بقاء القيم المدخلة عند الرجوع. _يعدّل لوحات المفاتيح ومعالج callback وحالة المحادثة._
- [ ] **[14] مسودة مستقلة لكل مستخدم:** حفظ مسودة العرض لكل مستخدم/محادثة واستعادتها بعد انقطاع المحادثة، مع انتهاء صلاحية واضح وعدم تسريب مسودة مستخدم لآخر. _ينشئ مخزن مسودات دائمًا ويعيد استخدام `Set/Get/Clear-PendingState`._
- [ ] **[1] شاشة مراجعة قبل `SHOW`:** عرض القالب والطبقة والقيم النهائية ثم انتظار زر تأكيد أو تعديل أو إلغاء، ولا يصل الأمر إلى Cinegy قبل التأكيد. _ينشئ حالة مراجعة ويعدّل `Invoke-ShowTemplateResult`._
- [ ] **[4] تأكيد «إخفاء الكل»:** تحويل الزر إلى خطوتين مع ملخص الطبقات التي ستُخفى، وإلغاء التأكيد تلقائيًا بعد مهلة قصيرة. _يعدّل `Invoke-HideAllLayers` ومعالج callback ويعيد استخدام لوحة الحالة._
- [ ] **[42] اختبار التنافس على الطبقة:** إضافة اختبارات Pester تثبت أن أول مشغل يحتفظ بالقفل، وأن الإلغاء/المهلة يحررانه، وأن مشغلًا آخر لا يستطيع تجاوزه. _يوسع `Tests/Bridge.Tests.ps1` ويختبر المهمة 2._
- [ ] **[41] اختبار انقطاع Cinegy أثناء `SHOW`:** محاكاة انقطاع Cinegy قبل الإرسال وأثناءه والتأكد من عدم تسجيل حالة بث ناجحة أو ترك قفل دائم. _يوسع اختبارات الأمر وحالة `OnAir`._

## المرحلة 2 — سرعة المشغل وإدارة المحتوى

- [ ] **[15] «تكرار مع تعديل»:** بدء مسودة جديدة من آخر إرسال مع السماح بتعديل أي قيمة قبل شاشة المراجعة، دون تغيير سجل الإرسال الأصلي. _يعدّل سجل آخر عرض ويعيد استخدام تدفق المسودة._
- [ ] **[16] سجل النصوص الأخيرة:** حفظ عدد محدود من القيم الأخيرة لكل حقل وإتاحتها كاختيارات سريعة، مع إزالة التكرار وعدم تسجيل الأسرار. _ينشئ مخزن تاريخ ذريًا ويعدّل لوحة إدخال الحقول._
- [ ] **[18] إدارة Presets من Telegram:** توفير شاشات المشرف لإنشاء Preset وتعديله وإعادة تسميته وحذفه مع معاينة قبل الحفظ ونسخة احتياطية. _يعدّل مخزن القوالب وواجهة المشرف ويعيد استخدام `Save-Config`/الحفظ الذري المناسب._
- [ ] **[19] لوحة طبقات مختصرة:** عرض جميع الطبقات وحالتها الحالية وأزرار الإجراء المسموح بها، مع تمييز ظاهر/مخفي/خارجي/غير معروف. _يعدّل `Get-LayersKeyboard` ويعيد استخدام `Get-CinegyLayerDashboard`._

## المرحلة 3 — الصحة والتشخيص

- [ ] **[8] أمر وزر `/health`:** إضافة ملخص صحي سريع متاح للجميع وزر له في القائمة، بينما تبقى التفاصيل الحساسة للمشرف. _يعدل تسجيل الأوامر والقائمة ويعيد استخدام `Get-AirTelemetryStatus`._
- [ ] **[9] قياس زمن الاستجابة:** قياس وعرض زمن Telegram وCinegy دون إبطاء دورة البوت أو اعتبار مهلة واحدة فشلًا دائمًا. _ينشئ قياسات زمنية ويعدّل مخرجات الصحة._
- [ ] **[10] آخر نجاح وآخر خطأ:** حفظ توقيت آخر فحص ناجح وآخر خطأ مختصر لكل خدمة وعرضهما في `/health`. _ينشئ سجل صحة صغيرًا ويعيد استخدام مراقبي Cinegy الحاليين._
- [ ] **[32] تشخيص شامل للمشرف:** إنشاء أمر مشرف يجمع الإصدار، الاتصال، صحة Cinegy، المسارات، الطوابير، الأقفال، الجدولة وآخر الأخطاء دون كشف Token أو محتوى حساس. _ينشئ منسق تشخيص ويعيد استخدام وظائف الحالة والسجل._
- [ ] **[37] تنبيه التشغيل وإعادة الاتصال:** إرسال تنبيه مشرف عند بدء البوت وعند استعادة اتصال Telegram أو Cinegy بعد انقطاع، مع منع تكرار الإشعار. _يعدّل دورة التشغيل ومراقب الصحة الحالي._

## المرحلة 4 — الجدولة الموثوقة

- [ ] **[25] مخزن جدول ذري:** إنشاء نموذج أحداث ذي معرف ثابت وحالة وتوقيت ومنطقة زمنية، وحفظه بملف مؤقت ثم استبدال آمن. _ينشئ مخزن جدولة جديدًا ويعيد استخدام نمط حفظ الحالة الدائمة._
- [ ] **[23] فحص ساعة الجهاز:** فحص معقولية الساعة والمنطقة الزمنية قبل قبول الجدولة، وإظهار الوقت الذي سيفهمه النظام للمستخدم. _ينشئ تحقق وقت ويعدّل تدفق الجدولة._
- [ ] **[20] جدولة `SHOW` مرة واحدة:** إضافة تدفق اختيار قالب وقيم ووقت، ثم تنفيذ الحدث مرة واحدة وتسجيل نتيجته الفعلية. _ينشئ واجهة الجدولة ومنفذ أحداث يعيد استخدام مسار `SHOW` الآمن._
- [ ] **[21] عرض الأحداث وإلغاؤها:** إظهار قائمة مرتبة بالأحداث القادمة وتفاصيلها المختصرة، مع إلغاء مؤكد يحدّث المخزن ذريًا. _ينشئ لوحة أحداث ويعيد استخدام معرفات الجدولة._
- [ ] **[22] التكرار اليومي والأسبوعي:** إضافة قاعدة تكرار واضحة وحساب الموعد التالي بعد اكتمال التنفيذ فقط، مع معالجة تغيير الساعة المحلية. _يوسع نموذج الجدولة ومنفذ الأحداث._
- [ ] **[24] منع التكرار بعد إعادة التشغيل:** تسجيل بدء/اكتمال الحدث بصورة دائمة واستخدام مفتاح تنفيذ لمنع إعادة حدث مكتمل عند تشغيل البوت. _يعدّل مخزن الجدولة ودورة الاستعادة._
- [ ] **[43] اختبار الجدولة وإعادة التشغيل:** تغطية الحدث الواحد والمتكرر والإلغاء وفشل الحفظ وإعادة التشغيل قبل/بعد التنفيذ عبر ساعة قابلة للمحاكاة. _يوسع `Tests/Bridge.Tests.ps1` ويختبر المهام 20–25._

## المرحلة 5 — حماية الإعدادات والاستعادة

- [ ] **[35] نسخة قبل تعديل الإعدادات:** إنشاء نسخة مؤرخة قبل أي تعديل دائم للإعدادات أو Presets، مع حد احتفاظ يمنع نمو المجلد بلا نهاية. _يعدّل `Save-Config` وينشئ مدير نسخ احتياطية._
- [ ] **[36] استعادة إعدادات سابقة:** إضافة شاشة مشرف تعرض النسخ الصالحة، تتحقق من JSON، تعرض ملخص الفرق، ثم تستعيد بعد تأكيد وتحتفظ بنسخة من الحالة الحالية. _ينشئ تدفق استعادة ويعيد استخدام التحقق والنسخ الاحتياطي._
- [ ] **[45] اختبار ترحيل الإعدادات:** إضافة عينات إصدارات قديمة واختبار القيم الافتراضية والحفظ والاستعادة وعدم فقد الإعدادات غير المعروفة. _يوسع اختبارات `Initialize-Settings` و`Save-Config`._
